# PRD — 한국형 Commitment App
> 버전: v1.0 (Phase 3 개정)  
> 제품 범위: iOS 우선 MVP  
> 문서 목적: 사용자 플로우, 기능 요구사항, 예외 처리, UX/UI 원칙을 정의한다.

---

## 1. 제품 목표

사용자가 **측정 가능한 약속을 만들고, 스스로 강제력의 수위를 정하고, 객관적으로 행동을 증명하고, 그 결과를 다시 확인**하게 한다.

### 강제력 모드
사용자는 각 약속마다 세 가지 중 하나를 고른다:
- **SELF (나만 확인)** — 증명은 남기되 돈은 걸지 않는다.
- **SOCIAL (친구에게 결과 알리기)** — 결과가 지정한 친구에게 공유된다. 금전 이동은 없다.
- **MONEY (돈까지 걸기)** — 실제 약속금을 걸고, 실패 시 환불되지 않는다.

세 모드 모두 **PASS / UNCERTAIN / FAIL**을 동일한 원칙으로 판정한다. 다른 것은 “실패했을 때 무엇을 잃는가”뿐이다.

### 핵심 사용자 행동
1. 약속 생성
2. 검증 방식 선택
3. **강제력 모드 선택** (SELF / SOCIAL / MONEY)
4. (MONEY일 때만) 약속금 설정 및 결제
5. 행동 수행
6. 증거 제출/자동 검증
7. PASS / UNCERTAIN / FAIL 판정
8. Appeal (MONEY 실패 시 특히 중요)
9. 다음 약속 생성

## 3. 온보딩

### 목표
- 앱의 강제력 개념을 먼저 이해시킨다.
- 가입 전에 가치가 느껴지게 한다.
- 60초 안에 첫 계약 후보까지 도달하게 한다.

### 권장 플로우
1. **Intro**
   - 헤드라인: “나와 한 약속, 이번엔 진짜 지켜봐요.”
   - 서브: “못 지키면 실제 약속금이 걸려 있어요.”
   - CTA: `시작하기`

2. **문제 공감**
   - “세운 목표를 중간에 포기한 적 있나요?”
   - 답변: 자주 / 가끔 / 거의 없음
   - 이 질문은 개인화 목적이며 필수 아님

3. **목표 선택**
   - 운동
   - 공부
   - 독서
   - 명상
   - 일찍 일어나기
   - SNS 덜 보기
   - 배달 덜 시키기
   - 직접 만들기

4. **제품 원리**
   - “약속을 정하고”
   - “했다는 걸 증명하고”
   - “못 지키면 약속금을 잃어요”

5. **Notification Permission**
   - OS 권한 요청 전 설명
   - “마감 전에 알려드릴게요”
   - CTA: `알림 받기`
   - Secondary: `나중에`

6. **가입**
   - Apple
   - Google
   - Email
   - 약관 동의

### 금지
- 가입 전에 10개 이상의 설문을 요구하지 않음
- 유입경로 질문은 첫 세션이 아니라 이후에 수집 가능
- “당신의 성공률은 94.2%가 됩니다” 같은 개인 예측성 카피는 근거 없이 사용하지 않음

## 4. 약속 생성 Wizard

### 전체 단계
**목표 → 규칙(스케줄) → 증명 방식 → Proof Rule → 강제력 선택 → (조건부) 강제력별 설정 → 최종 확인 → 서명 → 시작**

조건부 단계는 선택한 강제력 모드에 따라 다음과 같이 분기한다.

| 모드 | 추가 단계 |
|---|---|
| **SELF** | 없음 (바로 최종 확인) |
| **SOCIAL** | 수락된 친구 1명 지정 (진행/결과만 공유) |
| **MONEY** | 약속금 설정 → 서버 quote → 결제 확인 |

SELF/SOCIAL에서는 결제 화면, 최대 손실 UI, `0원 걸림` 같은 문구가 절대 등장하지 않는다.

### 4.1 목표 선택
헤드라인: `무엇을 꼭 하게 만들고 싶나요?`

템플릿:
- 오전 7시까지 일어나기
- 헬스장 가기
- 60분 공부하기
- 책 20페이지 읽기
- 20분 명상하기
- 인스타그램 30분 이하
- 배달음식 주문하지 않기
- 직접 만들기

### 4.2 규칙 설정
목표 유형별 UI를 다르게 제공한다.

예시 — 기상
- 시간
- 요일
- 증명 마감시간

예시 — 운동
- 주 N회
- 특정 요일 / 자유요일
- 장소
- 회차별 마감

예시 — 공부
- 하루 N분
- 주 N회
- 시작 가능 시간/마감시간

### 4.3 반복 방식
- 한 번만
- 매일
- 특정 요일
- 주 N회
- 사용자 지정

### 4.4 검증 방식
MVP:
- `사진으로 증명`
- `장소로 증명`
- `집중 타이머로 증명`
- `내가 직접 확인`
- `친구가 확인`

목표에 따라 추천순서가 다름.

예:
- 헬스장 → GPS 우선
- 기상 → 사진 우선
- 공부 → 타이머 우선
- 금주 → Self/Friend Verify 우선

### 4.5 Proof Rule
예:
- “오전 7:15까지 아침 식사 사진을 찍어요”
- “오후 9시 전까지 지정 헬스장 150m 안에 들어와요”
- “앱 타이머로 60분을 채워요”

### 4.6 강제력 선택 (Enforcement)
헤드라인: `어떻게 지키게 만들까요?`

카드 3장:
1. **나만 확인할게요** — “증명은 남기되, 돈은 걸지 않아요.”
2. **친구에게 결과를 알려주세요** — “혼자만 아는 약속보다 더 지키기 쉬워져요.”
3. **돈까지 걸고 확실히 할게요** — “못 지키면 실제 약속금을 돌려받지 못해요.”

MVP 상태:
- SELF 완전 지원.
- MONEY 완전 지원. 결제 → 서명 → 활성화 → 정산 → 종료 시 aggregate 환불까지 MockPaymentProvider로 end-to-end 동작. 실제 한국 PG는 provider/credentials 확정 후 교체.
- SOCIAL은 수락된 친구 1명에게 진행/결과를 보여준다. Stake/Payment/Ledger는 없다.
- Friend Verify는 수락된 친구 1명이 회차 완료를 승인/거절한다. 거절은 잠정 FAIL이며 Appeal/Grace/정산을 우회하지 않는다. 미응답·차단은 UNCERTAIN이며 금전 손실이 되지 않는다.
- Shared Commitment는 같은 목표의 컨테이너일 뿐이며 돈·정산·Grace를 갖지 않는다. 각 참가자가 독립 Commitment를 만든다.

### 4.7 (MONEY 모드) 약속금
헤드라인: `못 지키면 얼마를 걸까요?`

추천 금액과 상한은 서버 `StakePolicy` API에서 받는다. 클라이언트는 상한을 하드코딩하지 않는다.

Tier 1 (신규 사용자) 예시:
- ₩3,000 / ₩5,000 / ₩10,000 / ₩30,000
- 직접 입력 (서버 상한 준수)

표시:
- 이번 약속 약속금 (회차 수와 곱하지 않음)
- 총 횟수 / 엄격도 / 허용 FAIL
- 이번 Commitment 최대 손실 = 약속금
- 월간 남은 손실 한도

예:
> 이번 약속에 ₩30,000을 걸어요.  
> 총 10번 중 9번 이상 지키면 성공이에요.  
> 1번까지는 놓쳐도 괜찮아요.  
> 성공하면 ₩30,000 전액을 돌려받아요. 부분 환불은 없어요.

큰 금액 확인:
> "금액이 큰 약속이에요"  
> 이번 약속에서 최대 ₩150,000을 돌려받지 못할 수 있어요.  
> [이 금액으로 할게요] [금액 다시 고르기]

카피는 도박/공포 조장이 아니라 사용자가 자신의 선택을 다시 한 번 확인하는 톤으로 쓴다.

### 4.8 최종 계약 확인
모드별로 문구가 갈라진다.

**MONEY 예:**
> 월·수·금 오후 9시까지 헬스장에 가요.  
> 지정 장소 150m 안에서 GPS로 증명해요.  
> 이번 약속에 ₩30,000을 걸어요.  
> 총 10번 중 9번 이상 지키면 성공이에요.  
> 성공하면 전액 환불, 계약 실패면 환불되지 않아요.

**SELF 예:**
> 매일 오후 10시까지 60분 공부해요.  
> 집중 타이머로 증명해요.  
> 돈은 걸지 않고 내 기록으로 확인할게요.

CTA (양쪽 모두): `이대로 약속할게요`

### 4.9 (MONEY 모드) 결제
- 약속 기간 최대금액 선결제
- 카드/간편결제
- 결제 실패 시 약속 활성화 불가
- SELF/SOCIAL 약속은 이 화면 자체가 존재하지 않는다.

### 4.10 서명
헤드라인: `마지막으로, 직접 약속해요.`

- 손가락 서명
- 실제 법률 효력 목적이 아니라 commitment ritual
- “서명은 약관 동의와 별개”를 내부적으로 구분
- MONEY: `결제 후 30분 안에 서명을 마쳐주세요.` / `시간이 지나면 전액 환불돼요.`
- CTA: `서명하고 시작하기` · 보조: `약속 취소하기` (확인 후 전액 환불, 몰수 표현 금지)
- 취소/만료 후: `환불 처리 중` / `환불 완료` / `환불 지연`

## 5. Home

### 목표
“오늘 무엇을 해야 하는지”, 그리고 걸린 돈이 있다면 “얼마가 걸려 있는지”를 3초 내 파악.

### 상단 요약
- 오늘의 약속 개수는 항상 표시한다.
- 오늘 회차 중 MONEY 모드 회차의 at-risk 합계는 있을 때만 표시한다.

예 (혼합):
> 오늘 지켜야 할 약속 3개  
> 오늘 걸린 약속금 ₩10,000

예 (돈 걸린 약속이 오늘 없음 or 사용자가 SELF/SOCIAL만 씀):
> 오늘 지켜야 할 약속 3개

**절대 만들지 않는 UI**: `오늘 걸린 약속금 ₩0`, `0원 걸림`. 돈 UI는 관계 없을 때 완전히 사라진다.

### 카드
공통 필드: 약속명, 마감, 남은 시간, 검증 방식, 상태, CTA.

모드별 카드 예시:

**MONEY:**
> 헬스장 가기  
> 오후 9시까지  
> 5,000원 걸림  
> [지금 증명하기]

**SELF:**
> 60분 공부하기  
> 오후 10시까지

**SOCIAL:** 지정한 친구 1명에게 진행/결과만 공유. 친구는 결과를 바꾸지 않는다.
> 매일 20페이지 읽기  
> 오후 11시까지

## 6. 증명 제출

### 사진
- 앱 카메라 우선
- 갤러리 업로드는 기본 비허용
- 촬영시간 저장
- 필요 시 위치 메타데이터 저장
- AI 판정
- 증거 삭제 정책 적용

### GPS
- 사전 저장된 위치
- 기본 반경 100~200m
- 서버 시간 기준
- 위치권한 필수
- mock location 의심 시 UNCERTAIN

### Focus Timer
- 목표 시간
- 중도 종료 정책
- background 정책
- 서버 heartbeat 저장

### Self Verify
- 마감 후 일정 시간 내 성공/실패 직접 선택
- Self Verify는 고위험 약속금 제한 가능

### Friend Verify
- 친구가 회차 완료만 승인/거절한다. 승인=PASS, 거절=잠정 FAIL, 미응답=UNCERTAIN.
- verifier가 직접 금전적 이익을 얻지 않음. 증거/Stake/Appeal 상세는 공유하지 않는다.

## 7. 판정 엔진

### 상태
- `PASS`
- `UNCERTAIN`
- `FAIL`

### 정책
- AI 확신도가 낮으면 UNCERTAIN
- 서비스 장애는 FAIL로 처리하지 않음
- 권한 이슈는 사전 경고
- 마감 직전 제출은 서버 수신시간 기준

### UX
결과 UI는 모드별로 문구가 갈라진다. 판정 원리는 동일하다.

**PASS — MONEY:**
- `약속을 지켰어요`
- `₩10,000을 지켰어요`

**PASS — SELF:**
- `약속을 지켰어요`
- `오늘도 해냈어요`

**UNCERTAIN (모드 공통):**
- `한 번 더 확인이 필요해요`
- `아직 실패로 처리하지 않았어요`
- 추가 증거 요청 가능

**FAIL — MONEY:**
- `약속을 놓쳤어요`
- `₩10,000이 걸린 회차예요`
- Appeal CTA
- 결과 화면에서는 “미환불이 확정됐다”, “돈을 잃었다”고 표현하지 않는다. 금전 상태는 정산(Settlement)에서만 파생되며, 약속이 끝나야 `돌려받지 못한 금액`이 확정된다.

**금전 상태 표기 (MONEY 전용, 정산에서 파생):**
`결제 중` · `약속금 걸림` · `환불 예정` · `환불 중` · `환불 완료` · `결제 실패` · `환불 지연` · `정산 완료`.
전액 몰수(all FAIL)는 `정산 완료`이며 “환불 완료 0원”을 쓰지 않는다. SELF/SOCIAL에는 절대 노출하지 않는다.

**FAIL — SELF:**
- `약속을 놓쳤어요`
- `다음 약속은 이어가볼까요?`
- 사용자를 부끄럽게 만드는 카피는 절대 사용하지 않는다.

## 8. 결제/환불 로직 (MONEY 모드 전용)

이 섹션은 오직 MONEY 모드로 생성된 약속에만 적용된다. SELF/SOCIAL 모드는 결제/환불 로직을 갖지 않는다.

### 기본 구조
- 반복 약속의 전체 최대금액 선결제
- 회차별 성공금액 환불/결제취소
- 회차별 실패금액 미환불

### 예
월/수/금 × ₩5,000 = ₩15,000 선결제

- 월 성공 → ₩5,000 환불 대상
- 수 실패 → ₩5,000 미환불
- 금 성공 → ₩5,000 환불 대상
- 기간 종료 후 총 ₩10,000 환불 또는 회차별 즉시 환불

### 권장 MVP
회차별 즉시 환불보다 **기간 종료 후 일괄 정산**을 권장.
- 환불 API 호출 횟수 감소
- 취소/정산 단순화
- 사용자가 최대 위험금액을 계속 체감

### 표시
- 총 선결제
- 이미 지킨 금액
- 현재 위험 금액
- 실패 확정 금액
- 환불 예정 금액

## 9. Appeal

### 진입
MONEY 최종 FAIL 기록/상세 → `결과에 이의 제기하기`
(UNCERTAIN, system_hold, PASS, VOID, SELF, SOCIAL에는 노출하지 않는다.)

### 입력
- 사유 카테고리
- 짧은 설명
- 새 증거 업로드 없음. 기존 증거와 판정 메타데이터만 검토한다.

### 자격
- 소유자만, 회차당 1회
- FAIL 확정 후 7일 (서버 `APPEAL_WINDOW_SECONDS`). 기간 내 제출분은 만료 후에도 검토 가능.
- 제출만으로 돈·판정은 바뀌지 않는다.

### 상태
- 검토 중
- 승인됨 · 추가 환불 예정/완료/지연
- 기각됨 + 사용자에게 보이는 이유

### 결과
승인 (`correctedResult` = PASS 또는 VOID):
- 원래 VerificationResult / Settlement / Ledger는 불변. `originalResult`와 `effectiveResult`를 분리 노출.
- 정산 전 승인: 정산이 `correctedResult`를 소비. PASS/VOID는 환불 대상. reversal 없음.
- 몰수 후 승인: 원래 forfeit을 가리키는 reversal 1건 + 해당 회차 금액의 추가 환불 1건 (원래 결제 수단). payout/유저 간 이체 아님.
- 일반 종료 환불은 계속 합산 1회. 추가 환불은 이의 정정에만 허용.

기각:
- 원장·결제 변동 없음.

### 원칙
- 사용자가 돈을 잃는 구조이므로 Appeal은 핵심 기능
- AI만으로 최종 기각하지 않는 정책을 장기적으로 고려
- MVP 초기에는 운영자 수동 검토 (기존 admin auth + append-only audit)

## 11. Weekly Recap

사용자 IANA 타임존 기준 **직전 월요일–일요일**을 월요일 로컬 09:00(설정 가능)에 1회 생성한다. `(userId, localWeekStart)` 유일. 회차가 없으면 생성·푸시하지 않는다.

표시(유효 결과 기준, Appeal 승인 시 correctedResult):
- due / PASS / FAIL / VOID / unresolved
- `completionRate = PASS / (PASS + FAIL)`, 분모 0이면 null
- MONEY 회차가 있을 때만 금액: 지킨 금액(유효 PASS), 정산된 순손실(완료된 항소 환불/reversal 반영), 환불 대기/지연은 별도
- VOID는 성공·몰수가 아니다. 행동 FAIL은 정산 전에 손실 금액으로 보이지 않는다.

## 12. Atomic Habits 적용

### Make it Obvious
약속에 행동/시간/장소를 명확히 설정.

### Make it Attractive
친구 공개, 성공 리액션, 향후 앱 Unlock.

### Make it Easy
템플릿, 추천 규칙, 추천 Proof.

### Make it Satisfying
즉시 PASS, 지킨 돈, 스트릭, 리캡.

### Habit Contract
약속금 + 친구 공개 + 증거 검증.

### Never Miss Twice
실패 다음 회차에 복구 UX 제공.

> “운동하는 사람으로 한 번 더 증명했어요.”

## 13. UX Writing Guide — Toss-inspired

> Toss의 문구를 복제하지 않고, **짧고 명확하고 사용자의 다음 행동이 보이는 원칙**만 참고한다.

### 원칙
- 존댓말
- 한 문장에 한 가지 정보
- 명사형보다 동사형
- 금융/법률 용어는 일상어로 번역
- 돈이 걸리는 내용은 가장 명확하게
- 실패를 비난하지 않음
- 사용자가 무엇을 해야 하는지 바로 보여줌
- 버튼에는 결과를 예측할 수 있는 동사 사용

### Bad → Good
- `Challenge configuration` → `약속을 정해볼까요?`
- `Evidence submission` → `했다는 걸 보여주세요`
- `Penalty amount` → `못 지키면 얼마를 걸까요?`
- `Forfeit failed` → `약속을 놓쳤어요`
- `Appeal` → `결과에 이의 제기하기`
- `Refund pending` → `환불하고 있어요`

### 버튼
- `다음`
- `이대로 할게요`
- `증명할게요`
- `약속 시작하기`
- `다시 확인해 주세요`
- `다음 주도 이어갈게요`

## 15. 안전/정책

### 금전 Stake 제한 대상 (MONEY 모드 전용)
- 극단적 식단/체중감량
- 과도한 운동
- 약 복용 중단
- 자해/자살 관련
- 위험 운전/위험 행동
- 범죄
- 미성년자 사용

### 위험 목표 처리
- AI/룰 기반 목표 분류
- MONEY 모드 stake 비활성화 (`stake_disallowed`) — 하지만 SELF/SOCIAL 모드로는 여전히 만들 수 있는 경우가 있다.
- 명백히 위험한 목표(자해/약 복용 중단 등)는 강제력 모드와 무관하게 생성 자체를 차단한다.
- 사용자에게는 공포를 조장하지 않는 톤으로 안내한다.

### StakePolicy 티어 (MONEY 모드 상한)
StakePolicy는 서버가 강제한다. 클라이언트는 상한을 하드코딩하지 않는다.

| 티어 | 회차당 최대 | Commitment 최대 손실 | 월 누적 손실 한도 |
|---|---|---|---|
| Tier 1 (신규) | ₩30,000 | ₩150,000 | ₩300,000 |
| Tier 2 (Established) | ₩50,000 | ₩300,000 | ₩500,000 |
| Tier 3 (Verified) | ₩100,000 | ₩500,000 | ₩1,000,000 |

- 신규 사용자는 자동으로 Tier 1.
- Tier 상향은 자동화하지 않음 (MVP). dev/admin fixture로만 지정.
- Tier와 값은 서버 설정으로 조정 가능하며 법무/PG 검토 결과에 따라 재조정된다.
- Tier 1 추천 금액: 3,000 / 5,000 / 10,000 / 30,000 / 직접 입력.

## 16. 주요 Edge Case

- 앱/서버 장애 → FAIL 금지
- 인터넷 끊김 → 로컬 증거 임시 저장 + 재전송
- GPS 권한 OFF → 마감 전에 반복 경고
- 시간대 변경 → 계약 생성 시 timezone 고정
- 카드 결제 실패 → 약속 비활성
- 환불 실패 → 자동 retry + CS
- 탈퇴 요청 → 진행 중 약속 정산 후 처리
- 반복 약속 중간 취소 → `cancellationRequestedAt` 이후 회차만 VOID. 24시간 고지가 새 금전 노출을 만들지 않는다. 이미 열린/검토/증거/최종/항소 회차는 유지. FAIL은 항소 마감 또는 기각 후에만 확정. 환불은 최종 정산 때 1회.
- 마감 후 수정 → 불가
- 친구 미응답 → UNCERTAIN/system-hold. FAIL·Grace·정산 없음.
- AI 오판 → Appeal
- 동일 사진 재사용 → hash 탐지
