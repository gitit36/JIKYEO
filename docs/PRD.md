# PRD — 한국형 Commitment App
> 버전: v0.9  
> 제품 범위: iOS 우선 MVP  
> 문서 목적: 사용자 플로우, 기능 요구사항, 예외 처리, UX/UI 원칙을 정의한다.

---

## 1. 제품 목표

사용자가 **측정 가능한 약속을 만들고, 약속금을 걸고, 객관적으로 행동을 증명하고, 결과에 따라 환불/미환불을 경험**하게 한다.

### 핵심 사용자 행동
1. 약속 생성
2. 검증 방식 선택
3. 약속금 설정 및 결제
4. 행동 수행
5. 증거 제출/자동 검증
6. 성공 또는 실패
7. Appeal
8. 다음 약속 생성

## 3. 온보딩

### 목표
- 앱의 강제력 개념을 먼저 이해시킨다.
- 가입 전에 가치가 느껴지게 한다.
- 60초 안에 첫 계약 후보까지 도달하게 한다.

### 권장 플로우
1. **Intro**
   - 헤드라인: “나와 한 약속, 이번엔 진짜 지켜봐요.”
   - 서브: “못 지키면 실제 약속금이 걸려 있어요.”
   - CTA: `시작하기`

2. **문제 공감**
   - “세운 목표를 중간에 포기한 적 있나요?”
   - 답변: 자주 / 가끔 / 거의 없음
   - 이 질문은 개인화 목적이며 필수 아님

3. **목표 선택**
   - 운동
   - 공부
   - 독서
   - 명상
   - 일찍 일어나기
   - SNS 덜 보기
   - 배달 덜 시키기
   - 직접 만들기

4. **제품 원리**
   - “약속을 정하고”
   - “했다는 걸 증명하고”
   - “못 지키면 약속금을 잃어요”

5. **Notification Permission**
   - OS 권한 요청 전 설명
   - “마감 전에 알려드릴게요”
   - CTA: `알림 받기`
   - Secondary: `나중에`

6. **가입**
   - Apple
   - Google
   - Email
   - 약관 동의

### 금지
- 가입 전에 10개 이상의 설문을 요구하지 않음
- 유입경로 질문은 첫 세션이 아니라 이후에 수집 가능
- “당신의 성공률은 94.2%가 됩니다” 같은 개인 예측성 카피는 근거 없이 사용하지 않음

## 4. 약속 생성 Wizard

### 전체 단계
**목표 → 규칙 → 증명 → 약속금 → 친구 공개 → 최종 계약 확인 → 결제 → 서명 → 시작**

### 4.1 목표 선택
헤드라인: `무엇을 꼭 하게 만들고 싶나요?`

템플릿:
- 오전 7시까지 일어나기
- 헬스장 가기
- 60분 공부하기
- 책 20페이지 읽기
- 20분 명상하기
- 인스타그램 30분 이하
- 배달음식 주문하지 않기
- 직접 만들기

### 4.2 규칙 설정
목표 유형별 UI를 다르게 제공한다.

예시 — 기상
- 시간
- 요일
- 증명 마감시간

예시 — 운동
- 주 N회
- 특정 요일 / 자유요일
- 장소
- 회차별 마감

예시 — 공부
- 하루 N분
- 주 N회
- 시작 가능 시간/마감시간

### 4.3 반복 방식
- 한 번만
- 매일
- 특정 요일
- 주 N회
- 사용자 지정

### 4.4 검증 방식
MVP:
- `사진으로 증명`
- `장소로 증명`
- `집중 타이머로 증명`
- `내가 직접 확인`
- `친구가 확인`

목표에 따라 추천순서가 다름.

예:
- 헬스장 → GPS 우선
- 기상 → 사진 우선
- 공부 → 타이머 우선
- 금주 → Self/Friend Verify 우선

### 4.5 Proof Rule
예:
- “오전 7:15까지 아침 식사 사진을 찍어요”
- “오후 9시 전까지 지정 헬스장 150m 안에 들어와요”
- “앱 타이머로 60분을 채워요”

### 4.6 약속금
헤드라인: `못 지키면 얼마를 걸까요?`

추천:
- ₩3,000
- ₩5,000
- ₩10,000
- ₩20,000
- 직접 입력

표시:
- 회차당 금액
- 전체 기간 최대 손실
- 환불 예상 구조

예:
> 한 번 놓치면 ₩5,000  
> 이번 주 최대 ₩15,000이 걸려 있어요.

### 4.7 친구 공개
헤드라인: `누가 이 약속을 지켜볼까요?`

선택:
- 나만 보기
- 친구 1명에게 결과 공유
- 친구가 직접 검증

MVP에서 실패금은 친구에게 전달하지 않는다.

### 4.8 최종 계약 확인
예:
> 월·수·금 오후 9시까지 헬스장에 가요.  
> 지정 장소 150m 안에서 GPS로 증명해요.  
> 한 번 놓치면 ₩5,000을 돌려받지 못해요.  
> 이번 주 최대 ₩15,000이 걸려 있어요.

CTA: `이대로 약속할게요`

### 4.9 결제
- 약속 기간 최대금액 선결제
- 카드/간편결제
- 결제 실패 시 약속 활성화 불가

### 4.10 서명
헤드라인: `마지막으로, 직접 약속해요.`

- 손가락 서명
- 실제 법률 효력 목적이 아니라 commitment ritual
- “서명은 약관 동의와 별개”를 내부적으로 구분

CTA: `약속 시작하기`

## 6. 증명 제출

### 사진
- 앱 카메라 우선
- 갤러리 업로드는 기본 비허용
- 촬영시간 저장
- 필요 시 위치 메타데이터 저장
- AI 판정
- 증거 삭제 정책 적용

### GPS
- 사전 저장된 위치
- 기본 반경 100~200m
- 서버 시간 기준
- 위치권한 필수
- mock location 의심 시 UNCERTAIN

### Focus Timer
- 목표 시간
- 중도 종료 정책
- background 정책
- 서버 heartbeat 저장

### Self Verify
- 마감 후 일정 시간 내 성공/실패 직접 선택
- Self Verify는 고위험 약속금 제한 가능

### Friend Verify
- 친구가 성공/실패 선택
- verifier가 직접 금전적 이익을 얻지 않음

## 7. 판정 엔진

### 상태
- `PASS`
- `UNCERTAIN`
- `FAIL`

### 정책
- AI 확신도가 낮으면 UNCERTAIN
- 서비스 장애는 FAIL로 처리하지 않음
- 권한 이슈는 사전 경고
- 마감 직전 제출은 서버 수신시간 기준

### UX
PASS:
- `약속을 지켰어요`
- `₩5,000을 지켰어요`

UNCERTAIN:
- `한 번 더 확인이 필요해요`
- 추가 증거 요청

FAIL:
- `약속을 놓쳤어요`
- 실패 이유
- 미환불 금액
- Appeal CTA

## 8. 결제/환불 로직

### 기본 구조
- 반복 약속의 전체 최대금액 선결제
- 회차별 성공금액 환불/결제취소
- 회차별 실패금액 미환불

### 예
월/수/금 × ₩5,000 = ₩15,000 선결제

- 월 성공 → ₩5,000 환불 대상
- 수 실패 → ₩5,000 미환불
- 금 성공 → ₩5,000 환불 대상
- 기간 종료 후 총 ₩10,000 환불 또는 회차별 즉시 환불

### 권장 MVP
회차별 즉시 환불보다 **기간 종료 후 일괄 정산**을 권장.
- 환불 API 호출 횟수 감소
- 취소/정산 단순화
- 사용자가 최대 위험금액을 계속 체감

### 표시
- 총 선결제
- 이미 지킨 금액
- 현재 위험 금액
- 실패 확정 금액
- 환불 예정 금액

## 9. Appeal

### 진입
FAIL 상세 화면 → `다시 확인 요청`

### 입력
- 사유
- 추가 사진/문서
- 선택적 코멘트

### 상태
- 제출
- 검토 중
- 승인
- 기각

### 결과
승인:
- FAIL → PASS 또는 VOID
- 환불액 재계산
- 성공률/스트릭 복구

기각:
- 미환불 유지

### 원칙
- 사용자가 돈을 잃는 구조이므로 Appeal은 핵심 기능
- AI만으로 최종 기각하지 않는 정책을 장기적으로 고려
- MVP 초기에는 운영자 수동 검토 가능

## 12. Atomic Habits 적용

### Make it Obvious
약속에 행동/시간/장소를 명확히 설정.

### Make it Attractive
친구 공개, 성공 리액션, 향후 앱 Unlock.

### Make it Easy
템플릿, 추천 규칙, 추천 Proof.

### Make it Satisfying
즉시 PASS, 지킨 돈, 스트릭, 리캡.

### Habit Contract
약속금 + 친구 공개 + 증거 검증.

### Never Miss Twice
실패 다음 회차에 복구 UX 제공.

카피:
> “한 번 놓친 건 괜찮아요. 다음 약속만 이어가요.”

### Identity
과도한 철학적 질문 대신 결과에 자연스럽게 노출.
> “운동하는 사람으로 한 번 더 증명했어요.”

## 13. UX Writing Guide — Toss-inspired

> Toss의 문구를 복제하지 않고, **짧고 명확하고 사용자의 다음 행동이 보이는 원칙**만 참고한다.

### 원칙
- 존댓말
- 한 문장에 한 가지 정보
- 명사형보다 동사형
- 금융/법률 용어는 일상어로 번역
- 돈이 걸리는 내용은 가장 명확하게
- 실패를 비난하지 않음
- 사용자가 무엇을 해야 하는지 바로 보여줌
- 버튼에는 결과를 예측할 수 있는 동사 사용

### Bad → Good
- `Challenge configuration` → `약속을 정해볼까요?`
- `Evidence submission` → `했다는 걸 보여주세요`
- `Penalty amount` → `못 지키면 얼마를 걸까요?`
- `Forfeit failed` → `약속을 놓쳤어요`
- `Appeal` → `다시 확인 요청`
- `Refund pending` → `환불하고 있어요`

### 버튼
- `다음`
- `이대로 할게요`
- `증명할게요`
- `약속 시작하기`
- `다시 확인해 주세요`
- `다음 주도 이어갈게요`

## 16. 주요 Edge Case

- 앱/서버 장애 → FAIL 금지
- 인터넷 끊김 → 로컬 증거 임시 저장 + 재전송
- GPS 권한 OFF → 마감 전에 반복 경고
- 시간대 변경 → 계약 생성 시 timezone 고정
- 카드 결제 실패 → 약속 비활성
- 환불 실패 → 자동 retry + CS
- 탈퇴 요청 → 진행 중 약속 정산 후 처리
- 반복 약속 중간 취소 → 미래 회차만 취소
- 마감 후 수정 → 불가
- 친구 미응답 → Friend Verify 정책에 따라 UNCERTAIN/Appeal
- AI 오판 → Appeal
- 동일 사진 재사용 → hash 탐지

## 17. MVP 출시 기준
